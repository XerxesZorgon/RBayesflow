# ADR-006: Posit Assistant Integration Strategy

**Status:** Accepted  
**Date:** 2026-09-08  
**Deciders:** John Peach  
**Linked specs:** SDD §4 (Modes), DESIGN.md §5 (Posit Assistant)

---

## Context

Posit Assistant (the LLM layer embedded in RStudio) must read live session state to provide context-aware diagnostic interpretation and workflow guidance. The key questions are:

1. **System prompt conventions** — how does RBayesflow inject its context (mode, stage, diagnostic state) into the Posit Assistant system prompt or context window?
2. **`wf_state` serialization format** — what format does `wf_state` take when passed to Posit Assistant as context?
3. **Code proposal safety** — how do we ensure LLM-suggested code appears in a non-executable preview before the user runs it?

Three approaches to `wf_state` serialization:

**Option A — JSON (via `jsonlite::toJSON()`)**  
- Human-readable, machine-parsable
- Standard format for LLM context injection
- All `wf_state` fields (mode, stage, prior text, diagnostic summary, audit trail) serialize cleanly to JSON
- Easy to reconstruct in any tool that reads JSON

**Option B — YAML**  
- Also human-readable; slightly more compact than JSON for nested structures
- Less standard for programmatic LLM context injection
- Requires the `yaml` package

**Option C — `dput()` output**  
- R-native; produces valid R code that reconstructs the object
- Difficult for an LLM to parse contextually (high token cost; unfamiliar format)
- Not recommended for LLM consumption

Three approaches to system prompt conventions:

**Option X — Document-level header in the `.qmd` file**  
- Inject mode/stage as YAML frontmatter; Posit Assistant reads the document context
- Passive; relies on Posit Assistant to notice and act on it

**Option Y — Explicit context file (`wf_context.json` in the project root)**  
- `wf_state` serialized to a file that RStudio and Posit Assistant can reference
- Generated by `export_context(wf)` at the start of each session
- Can be regenerated at any point without disrupting the session

**Option Z — In-session object only**  
- Posit Assistant reads `wf_state` directly from the live R environment
- Depends on Posit Assistant's ability to introspect R objects (currently available in recent RStudio versions via the "Data" pane context)

---

## Decision

**Serialization: Option A (JSON via `jsonlite::toJSON()`).**  
**System prompt: Option Y + Option Z combined.**

`export_context(wf)` serializes `wf_state` to `wf_context.json` in the project root (Option Y). This file is the primary vehicle for session continuity (survives R session restarts) and for explicit Posit Assistant prompting (users can paste the JSON or reference the file). Posit Assistant also reads the live R environment (Option Z) when available, providing the richest context. Option X (document-level YAML header) is used as a lightweight supplement in the Quarto template frontmatter, injecting `mode` and `stage` for document-level awareness.

Code proposals from Posit Assistant appear in the Posit Assistant panel as suggested code blocks, which are only inserted into the editor on explicit user action (Posit Assistant's standard behavior). No additional enforcement mechanism is required beyond documenting this in the README.

---

## Rationale

1. **JSON is the de facto standard for LLM context injection.** jsonlite is already available as a brms/tidybayes dependency; no new package needed.
2. **File-based context survives session restarts.** A student who closes RStudio and reopens the project gets back into context immediately via `wf_context.json`, without re-running the full pipeline.
3. **In-session introspection (Option Z) is the richest source** when available, but is not a stable Posit API. By using Option Y as the primary path, we degrade gracefully if Posit's API changes.
4. **Code proposal safety is Posit Assistant's default behavior.** The "insert into editor" button in the Posit Assistant panel already requires explicit user action. No custom enforcement is needed.

## Consequences

- **Positive:** `wf_context.json` gives Posit Assistant explicit, structured context with a single file reference.
- **Positive:** JSON schema is versioned (`rbayesflow_version` field), allowing format evolution without breaking old context files.
- **Positive:** Code proposal safety requires no custom implementation; Posit's default panel behavior is sufficient.
- **Negative:** `export_context(wf)` must be called explicitly to update the file after each major workflow step. **Mitigation:** each workflow phase script calls `export_context(wf)` as its last step; users are also prompted at the top of each session to run it.
- **Negative:** Posit Assistant's direct R-environment introspection (Option Z) is not a stable documented API and may change. **Mitigation:** Option Y (file-based) is the primary path; Option Z is additive.
- **Watch:** Revisit when Posit publishes a stable API for Posit Assistant context injection. A stable API would allow removing `export_context()` entirely and reading `wf_state` from the live session directly.
